## 1. 为什么改

### 1.1 大帧 bug（必修）

v1 帧头是 `type(uint16) + length(uint16)`，单帧最大 65535 字节。

- 历史分页 20 条 × 2000 字中文 ≈ 120KB
- Agent 长回复、100 条历史更不用说

超限时 `struct.pack("!HH")` 抛异常，服务端只打了 `回包失败`，客户端**连错误码都收不到，连接直接被断开**。已复现：

```
回包失败 ('127.0.0.1', 57758): 'H' format requires 0 <= number <= 65535
```

### 1.2 心跳只写了一半

原来只有 `router.py` 里的 pong 应答和一行注释「客户端定时发 ping」，但：

- 没有任何客户端真的发 ping（CLI 只打印 pong，bridge/前端搜不到 ping）
- 服务端不记录 `last_seen`，没有超时判定
- 没有 `SO_KEEPALIVE`

结果：杀进程能靠 FIN 清理，但**拔网线/挂起虚拟机/暂停进程**这种半开连接永远发现不了，用户会一直挂在在线列表里。

## 2. 协议 v2

```
+--------+---------+--------+----------------+-----------------+
| magic  | version | type   | length         | body (JSON)     |
| uint16 | uint8   | uint8  | uint32         | length 字节      |
| 0x5443 | 2       | 0-255  | 上限 2MB        | UTF-8           |
+--------+---------+--------+----------------+-----------------+
```

- `MAX_FRAME_BYTES = 2MB`；超过上限的**声明长度**直接判 `ProtocolError`，防止无限攒包
- `magic` 不对 / `version` 不对 → 抛 `ProtocolError`，服务端记录「协议错误」后只关这一条连接
- 发送侧：`FrameTooLarge` 不再让连接线程崩掉，回包处转成 `MSG_TOO_LONG` 错误帧；`broadcast` 超限只丢这一条并记日志
- 数据层双保险：历史分页按字节收缩（单页 ≤512KB，`more` 仍为 true）；Agent 回复落库前截断到 32KB

**兼容性**：客户端桥、命令行客户端、服务端必须一起升级（同一个目录里已同步改好）。前端 `dist` 不受影响——浏览器侧只认 WebSocket JSON。

## 3. 心跳与超时回收

| 位置 | 行为 |
| --- | --- |
| `client/socket_client.py` | `start_heartbeat()`：每 `CHAT_HEARTBEAT_SECONDS` 秒发 `{"type":"ping","seq":n,"ts":ms}`；`note_pong()` 用 seq 匹配发送时刻算 RTT |
| `client/bridge.py` | 桥连上服务端后启动同一个心跳线程；pong 在桥里消费，打印 `[Link] ... RTT 1ms`，不污染前端消息流 |
| `server/network/socket_server.py` | 收包时 `users.touch(conn)`（任何帧都算活着）；连接建立时开 `SO_KEEPALIVE` |
| `server/services/user_service.py` | 维护 `_conns: {socket: last_seen}`；`reap(timeout)` 关闭超时连接、清在线表 |
| `server/network/keepalive.py`（新增） | `IdleReaper` 后台线程，每 `CHAT_REAP_INTERVAL` 秒调一次 `reap`，回收后广播 `userlist` |
| `server/services/router.py` | pong 带回 `seq` 和 `server_time` |

终端日志示例：

```
[Heartbeat] silent 超过 6s 没有任何数据（阈值 6s），判定掉线并断开
[Heartbeat] 本轮回收 1 个连接：silent
```

## 4. 新增配置（`.env`）


测试环境：Windows + Python 3.13，独立测试库 `_verify/work.db`，端口 10286/10287，mock LLM 模拟 function calling。

| --- | --- |

## 7. 答辩演示脚本（约 3 分钟）

1. 用短超时启动服务端：
   ```bash
   set CHAT_IDLE_TIMEOUT=15
   set CHAT_REAP_INTERVAL=5
   set CHAT_HEARTBEAT_SECONDS=5
   python -m server.main
   ```
2. 三个客户端登录，正常群聊（证明基本功能）。
3. **正常关闭**一个客户端 → 立刻从成员列表消失（FIN 路径）。
4. **模拟异常掉线**：把某个客户端进程挂起（任务管理器"挂起"），或直接杀掉它的网络；
   约 15 秒后它从列表消失，服务端终端出现 `[Heartbeat] ... 判定掉线`，其余人聊天不受影响。
5. **大帧**：连续发几条长消息，然后翻历史 / 让 Agent 总结，连接不再断。
