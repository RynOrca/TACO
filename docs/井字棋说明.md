# 井字棋说明（人对 Agent / 人对人 / 观战）

> 两种牌桌：**人和 Agent**、**人和人**。共同点是「棋盘状态由服务端维护」——
> 不管是 Agent 还是另一位成员，都得按轮次走服务端校验过的落子流程，模型不能自己记棋盘。

---

## 1. 玩法

```
/game start             和 Agent 开一局（你执 X，先手）
/game invite 用户名      邀请另一位成员对弈（对方 /game accept 接受）
/game accept | decline  接受 / 拒绝邀请（120 秒内有效）
/game move 5            把棋子下在第 5 格（1-9，左上到右下）
/game watch             列出所有进行中的对局（右栏棋盘可直接看）
/game board | status    看当前棋盘 / 看战绩
/game quit              退出对局（人对人时判对方胜）
```

也可以直接在右侧「井字棋」面板里点格子落子：轮到你且格子为空时按钮可点，Agent 思考中整盘禁用，结束后给「再来一局」。

棋盘用文本渲染，数字是空位：

```
 1 │ 2 │ 3
───┼───┼───
 4 │ X │ 6
───┼───┼───
 7 │ O │ 9
```

每走一步都会广播一次**结构化棋局状态**（谁执什么、轮到谁、观战人数），群里只补一行简短提示
（不打整个棋谱，免得刷屏）。每个用户同一时间只在一盘棋里，但可以同时观战别人的棋。

### 三种视角

| 视角 | 侧栏棋盘 | 说明 |
| --- | --- | --- |
| 我是玩家（轮到我了） | 可点击 | 空位可点，已占的格子和对方回合都禁用 |
| 我是玩家（等对方） | 只读 + 「等待 xxx 落子」 | 人对人时等对方点，Agent 局等模型落子 |
| 我是旁观者 | 只读 + 「观战中」+「只读」标记 | 顶部显示 `A vs B · N 人观战`，多人多盘时下面可切换 |

邀请会在被邀请人的侧栏弹出卡片（带倒计时），点「接受」直接开局；超过 120 秒自动作废。
另外「找人下棋」区域会列出所有在线成员，一键发邀请。

## 2. 为什么状态放服务端

如果让模型"记住"棋盘，会出现：忘了上一步、重复占格、自己改棋局、前后矛盾。
所以 `server/services/game_service.py` 的 `Game` 持有唯一权威棋盘：

- `move(cell, mark)` 校验：轮次、范围、格子是否为空、是否已结束
- 胜负判定走 8 条连线；棋盘下满判平局
- Agent 的工具用**闭包**绑定当前这一盘：`game_tools(game, user_id)` 返回
  `game_get_board` / `game_move` 两个工具，模型只能看到函数名和参数，碰不到别的棋局

## 3. 一轮的完整链路

```
玩家输入 /game move 5
    ↓
GameService.move(5, "X")         服务端校验并落子
    ↓
广播「下在 5，Agent 思考中…」+ 棋盘
    ↓
Agent 线程池：run_detailed(prompt, extra_tools=game_tools)
    ↓
模型调用 game_move(cell)        服务端再次校验（轮次/O 方/空格）
    ↓
模型一句话点评 → 回复 + 棋盘广播回群里（带真实工具调用记录）
    ↓
若模型没落子/落子非法 → 本地 minimax 代打一步，并在消息里注明
```

模型这一轮最多 4 步 ReAct；`game_move` 的每次调用都会出现在 Agent 卡片的「真实工具调用」里，答辩可以直接展开。

## 4. 前端：可点击棋盘

服务端在开局、每次落子、Agent 落子、看棋盘、退出时，额外给**下棋本人**发一条结构化状态：

```json
{"type":"game","action":"state","board":["X","O"," "," "],"turn":"O",
 "over":false,"result":"","score":{"win":1,"lose":0,"draw":0}}
```

- `store.ts` 把它收进 `state.game`；`GamePanel` 用它渲染 3×3 按钮
- 只有 `turn === "X"`、未结束、格子为空时按钮可点，点击发 `{"type":"game","text":"move N"}`
- `action:"closed"` 时清空面板；结束后整盘禁用，显示结果、战绩和「再来一局」
- 群里其他人不会收到结构化状态（只看到文本播报），避免别人替你看棋
- 文本指令 `/game move N` 仍然保留，命令行客户端也能玩

## 5. 兜底策略

| 情况 | 行为 |
| --- | --- |
| 没配置 LLM / 调用失败 | Agent 回一句"暂不可用"，然后用 minimax 替它落子，棋局继续 |
| 模型没调 `game_move` | 同上，本地代打并在消息里注明 |
| 模型调了非法格 | 工具返回 `[ToolError] 可落子位置...`，模型可以重试；若最终仍没落子则本地代打 |
| 玩家抢跑 / 重复落子 | 服务端直接拒绝，返回 `BAD_MOVE` |
| 对局中退出 | 标记 `cancelled`，正在跑的 Agent 任务结束后不再写回棋局 |

## 7. 演示脚本（约 2 分钟）

1. 三个客户端登录，其中一个人在右侧面板点「开始一局」
2. 直接**点格子**落子，让其他人看群里的文本播报；展开 Agent 卡片里的「真实工具调用 1 次」，指出 `game_move(cell=…)`
3. 故意点已被占的格子（按钮是禁用的），再发 `/game move 5`，展示服务端拒绝
4. 下到分出胜负，面板显示结果、战绩和「再来一局」
5. （可选）把 `.env` 里的 `LLM_API_KEY` 清空重启，再走一步，展示"模型不可用也能继续下"的兜底

## 8. 断线与退出

| 场景 | 服务端行为 |
| --- | --- |
| 人对人时一方被心跳回收 / 关窗口 | 判对方胜，广播最终棋盘与结果，然后释放两个玩家名额 |
| 人对人时主动 `/game quit` | 同上（认输） |
| 人对 Agent 时玩家掉线 | 这盘直接取消（没有对手可判胜），广播 `closed` |
| 换号登录 / 多端登录 | 老连接的 finally 里会检查「这个人是否还在线」，还在线就不动他的棋局 |
| 结算之后 | 棋局快照保留给双方看结果，直到有人开新局或点「关闭」，超 5 分钟自动清理 |

## 9. 已知限制

- 棋局和战绩都在内存里，服务端重启后清空（历史消息里的棋盘文字播报还在）
- 每人同时只有一盘"自己的棋"，观战不限盘数；观战者离开不影响棋局
- 刷新页面后，侧栏面板要等下一次 `game` 状态消息、`/game watch` 或 `/game board` 才会恢复
- 邀请只能发给在线成员，离线成员收不到（`USER_OFFLINE`）
- Agent 的棋力取决于模型；想稳定赢可以用本地 minimax（现在只做兜底）
