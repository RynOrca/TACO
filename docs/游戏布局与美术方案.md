# 游戏布局与美术方案（原型：`client/ui/game-mode-mock.html`）

> 三套布局、三个游戏的界面与动效，先用一个 HTML 定稿，再接进 React。
> 直接浏览器打开该文件即可交互：顶部切布局，按 `1/2/3` 切游戏，`Esc` 回聊天。

## 一、三种布局，一套逻辑

| 布局 | 什么时候用 | 左栏 | 聊天 | 游戏台 | 右栏 |
| --- | --- | --- | --- | --- | --- |
| **聊天视图** | 默认 | 会话列表（264px） | 中间自适应 | 不显示 | 标签页：聊天室 / 游戏 / Agent |
| **专注游戏** | 开局、收到邀请、点游戏列表 | 折叠成 46px 图标条 | 左移成 320px 窄列 | 占据中间最大宽度 | 赛况：牌桌 / 本局记录 / 观战席（只读） |
| **剧场全屏** | 演示、投影、单人对 Agent | 隐藏 | 右下角 300px 浮层 | 全屏 | 隐藏 |

**切换逻辑（不是用户手动切）**

1. 进入对局（自己开局 / 接受邀请 / 点左侧游戏项）→ 自动进「专注游戏」
2. 一局结束 → 停在专注模式展示结果，不自动弹回（避免结果一闪而过）
3. `Esc` 或点「回聊天」→ 回聊天视图，对局在后台继续，左侧游戏项显示 ● 进行中
4. 剧场模式是显式选择（演示用），退出同样用 `Esc`

**为什么这么分**：聊天是常驻需求（不能真的"藏起来"），但下棋时棋盘必须是视觉焦点。把左栏折成图标条 + 聊天压到 320px，能同时保住"随时能说话"和"棋盘够大"；剧场模式则只在不需要聊天时用。

## 二、三个游戏的界面与动效

### 井字棋（已有，本次补动画）
- 9 格直角格子，悬停出现淡淡的 X 影子
- 落子用 `stroke-dashoffset` 把 X/O **一笔画出来**（0.45s）
- 获胜三格套荧光青柠底 + 撒彩带
- 状态：`轮到你（X）` / `等待 xxx 落子` / `观战中 · 轮到 xxx`

### 五子棋（新增）
- 15×15 交叉线棋盘，木色纸底 + 半透明格线，四个星位 + 天元
- **棋子落在交叉点**：统一 `left/top = calc(var(--cell) * (i + .5))`，格子间距 = `--cell`，四周留半格
- 落子动效：从 0.4 倍缩放 + 透明 → 轻微过冲到 1.06 → 落定，配投影
- 最后一手加荧光点，五连时整排呼吸发光
- 观战视角只读，鼠标悬停不显示落点提示

### 21 点（新增）
- 纸感牌桌：庄家区 / 下注区（筹码堆）/ 玩家区，三行结构
- 发牌：`rotateY(90deg)` → 0，逐张 90ms 延迟
- 庄家暗牌用斜纹牌背 + 荧光 T 字标记；停牌后**翻牌动画**揭示
- 超过 21 点：整桌轻抖 + 点数变红
- 赢牌：撒彩带；结果文案 `你赢了这局 / 庄家赢 / 平局 / 爆牌`

## 三、21 点的隐藏信息怎么保证（重点）

牌类游戏的漏洞不在 UI，而在**状态怎么下发**。三条硬规则：

1. **服务端持有唯一牌堆，按"每个连接"裁剪视图**
   ```python
   def view_for(table, viewer):
       if viewer == table.agent:            # Agent 只能看自己
           return {"hand": table.agent_hand, "upcards": table.player_upcards}
       if viewer in table.players:          # 玩家看自己 + 公共明牌
           return {"hand": my_hand, "upcards": others_upcards}
       return {"upcards": all_upcards, "hidden_count": n}   # 观战者只看明牌
   ```
   暗牌在服务端的 JSON 里根本不存在，客户端拿不到就不可能"改 UI 偷看"。

2. **Agent 的工具只能读自己的牌**
   `blackjack_get_hand()` 返回 Agent 的手牌与玩家**明牌**；`blackjack_hit()` / `stand()` 由服务端判定。
   玩家手牌、牌堆剩余顺序**永不进入**工具结果，也不写进 prompt。

3. **揭示时机由服务端决定**
   只有 `stand()` 之后才把暗牌补进广播，且广播的是"已揭示后的快照"，不是原始牌堆。

验收时可以现场演示：开 DevTools 看 WebSocket 帧，玩家手牌只出现在自己那条连接里；Agent 卡片的 `steps` 里也看不到对方牌面。

## 四、实现顺序（建议）

| 顺序 | 内容 | 工作量 | 复用 |
| --- | --- | --- | --- |
| 1 | 布局切换（专注 / 剧场）+ 左栏折叠 | 中 | 现有 SidePanel 拆标签页已经做完 |
| 2 | 五子棋（棋盘 + 胜负判定 + 轮次） | 中 | 牌桌模型、邀请、观战、断线判负**全部复用** |
| 3 | 21 点（牌堆 + 裁剪视图 + Agent 工具） | 大 | 邀请/观战复用，状态模型要单独一套 |
| 4 | 动效打磨（棋子落定、发牌、彩带、回合高亮） | 小 | CSS 动画，原型里已有成品 |

服务端改动边界：
- `game_service.py`：`Game` 抽象成 `GameRoom`（玩家/观战/轮次），井字棋与五子棋共用；`BlackjackTable` 单独实现但走同一套房间与邀请
- `chat_service.py`：`handle_game` 按 `game_kind` 分发；广播改为"每人一份裁剪视图"
- 前端：`GamePanel` 拆成 `Arena`（布局）+ `TicTacToeBoard` / `GomokuBoard` / `BlackjackTable`（各自动效）

## 五、已知取舍

- 五子棋的 Agent 棋力靠启发式候选点评分，LLM 只负责选点与点评；纯靠模型会下得很差
- 21 点不做分牌/保险/加倍（课程演示用不到，规则越少越不容易翻车）
- 剧场模式不做拖拽，浮层位置固定右下（原型里标注了"可拖拽"，实现时可去掉或加拖拽）
