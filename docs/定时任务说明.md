# 定时任务泛化说明

> 目标：把「只有定时总结」升级成通用定时任务模型，任务落库、可增删启停、重启不丢。
> 不涉及新闻抓取（需要外部 key / 网络，演示风险高），只保留 `summary` 和 `reminder` 两类。

---

## 1. 数据模型

新表 `scheduled_tasks`（`server/storage/db.py`）：

| 字段 | 说明 |
| --- | --- |
| `id` | 任务编号，`/task` 指令里用的就是它 |
| `kind` | `summary`（让 Agent 总结群聊）/ `reminder`（到点广播提醒，不经过模型） |
| `payload` | 提醒内容；summary 为空 |
| `interval_seconds` | `>0` 周期任务；`0` 一次性任务（跑完自动关闭） |
| `next_run` / `last_run` | UTC ISO 时间 |
| `enabled` | 0/1 |
| `created_by` / `room_id` | 谁创建、发到哪个房间 |
| `created_at` | 创建时间 |

索引 `(enabled, next_run)`，到期查询只扫 `enabled=1 AND next_run<=now`。

## 2. 调度器

`server/services/scheduler.py` 的 `TaskScheduler` 替换了原来的 `AutoSummaryScheduler`：

- 常驻线程每 `CHAT_TASK_TICK` 秒（默认 5s）扫一次到期任务
- **先把 `next_run` 推到下一次，再执行**，防止任务执行慢导致下一轮重复触发
- `summary` → 丢进 `ChatService` 的 Agent 线程池（不阻塞调度线程）
- `reminder` → 直接 `broadcast({"type":"system","msg":"⏰ 定时提醒：..."})`
- 周期任务如果服务端停机错过多个周期，只顺延到下一个周期，不补跑一堆积压
- 一次性任务如果停机期间到期，启动后补跑一次
- 单次任务异常只记日志，不会带走调度线程

## 3. 指令

| 输入 | 作用 |
| --- | --- |
| `/task list` | 列出全部任务（编号 / 类型 / 周期 / 下次时间 / 状态） |
| `/task add summary every:10` | 每 10 分钟让 Agent 总结一次 |
| `/task add reminder in:5 开会` | 5 分钟后广播一次提醒 |
| `/task add reminder every:30 起来活动` | 每 30 分钟提醒一次 |
| `/task del 3` / `/task on 3` / `/task off 3` | 删除 / 开启 / 暂停 |
| `/auto 5`、`/auto off`、`/auto now` | 保留兼容：等价于配置 / 暂停 summary 任务，`now` 立即执行一次 |

服务端解析 `{"type":"task","text":"..."}`，客户端只负责把 `/task` 后面的原文转发过去（Web 和命令行各加一行），避免两套解析逻辑。

## 5. 演示脚本（约 1 分钟）

1. 启动服务端（建议 `CHAT_TASK_TICK=1`，让触发更准点）
2. 客户端里输入：
   ```
   /task add reminder in:1 大家准备联调
   ```
3. 等 1 分钟，群里出现 `⏰ 定时提醒：大家准备联调`
4. `/task list` 看到该任务已变成「暂停」
5. 再输入 `/task add summary every:2`，两分钟后 Agent 自动总结并广播（有新消息时）
6. 重启服务端，`/task list` 里任务还在——这是"落库"最直接的证据

## 6. 已知限制

- 一次性任务重新开启时，固定按 1 分钟后触发（不支持指定绝对时间，如"明天 9 点"）
- 最小周期 1 分钟；演示时配合 `CHAT_TASK_TICK=1` 足够
- summary 任务仍受"至少 N 条新消息"门槛限制（`AGENT_AUTO_SUMMARY_MIN_MESSAGES`），没有新消息时到点会跳过
- 触发历史只体现在服务端日志，没有单独的"执行记录"表
