需要的工具：

1. read_recent_chat_history（读取指定会话的聊天记录）
作用：Agent 接到总结任务时，必须先拿到最近的聊天记录。（实验要求明确举例）
给大模型的描述：读取指定房间（群聊/私聊）最近的聊天记录。
参数：room_id（房间ID）, limit（读取条数，默认 20 或 50）。
真实执行逻辑：调用存储层的 DAO 函数，去 SQLite/MySQL 里查最近的记录，拼成字符串返回。
注意：记得做权限判断（比如只能读授权范围内的聊天，防止越权）。

2. save_agent_result（保存整理结果/待办事项）
作用：Agent 提取了待办事项或生成总结后，有时需要存入数据库（持久化），而不是发完就没了。（实验要求明确举例）
给大模型的描述：将生成的总结或待办事项保存到当前会话的记录中。
参数：room_id（房间ID）, content（整理好的文本）, type（类型：summary 或 todo）。
真实执行逻辑：将数据写入数据库的 agent_records 表或追加到 messages 表中。

3. search_chat_history（搜索历史消息）
作用：用户问“昨天谁提了关于周报的事？”，Agent 去数据库里搜。（实验要求明确举例）
给大模型的描述：在指定房间的历史聊天记录中搜索包含关键词的消息。
参数：room_id（房间ID）, keyword（搜索关键词）。
真实执行逻辑：调用数据库的 LIKE 查询（SELECT * FROM messages WHERE content LIKE '%keyword%'）。



推荐扩展工具（提升演示效果，显得系统很智能）

4. get_online_users（获取当前在线用户）
作用：如果用户让 Agent “@所有人 开会”，Agent 需要知道现在谁在线。
给大模型的描述：获取当前聊天室在线的用户名单。
参数：无。
真实执行逻辑：从 socket_server 或 user_service 中获取当前连接的 Socket 客户端列表。

5. get_group_members（获取群成员名单）
作用：用于 Agent 做点名、或者判断某个人是否在群里。
真实执行逻辑：查数据库的群成员关系表。
